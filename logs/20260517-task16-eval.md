## Why

Task 16 needs the evaluation surface for B1 sparse one-step runs while keeping the
actual SR metric computation deferred to B200 production hardware. The local test
therefore validates aggregation and required output keys without requiring a real
checkpoint, GPU, video IO, LPIPS, DISTS, or torchmetrics execution.

## Test Design

- Write a temporary validation JSON with two samples.
- Patch `eval.eval_sr._evaluate_one_video` to return synthetic per-video metrics.
- Patch `eval.eval_sr._measure_fps` to return synthetic 720p/1080p FPS.
- Assert `evaluate_checkpoint(...)` returns the documented metric keys.
- Assert the PSNR aggregation is the mean of the two synthetic samples.

## B200 Wiring Notes

`eval/eval_sr.py` intentionally leaves production-heavy helpers as
`NotImplementedError` stubs:

- `_evaluate_one_video(...)`
- `_measure_fps(...)`

Production B200 implementation still needs:

- `torchmetrics.image` for RGB-domain PSNR and SSIM.
- `lpips` with VGG backbone for RGB-domain LPIPS.
- `pyiqa` or official DISTS implementation.
- Sparse attention accounting for `1 - active_blocks / total_blocks` averaged
  across layers and heads.
- FPS benchmarking at 720p and 1080p in fp16, batch size 1, after 5 warmup
  chunks, excluding IO.
- Peak memory from `torch.cuda.max_memory_allocated()`.
